# Gallery Thing (NYC Photo Shows) — Project Brief
**Last updated:** 2026-10-24
*A personal gallery planning tool for Josh Seiden. Lives in `gallery/` inside the `joshseiden/photography-portfolio` repo.*

---

## Goals

A mobile-first, single-page web app for planning and walking NYC photography gallery crawls. Plan on the laptop, walk with the phone.

- Show photography only
- Same personal state (saved / seen / hidden) on every device (Build 2)
- Better, cheaper data gathering; broader gallery coverage (later builds)

Personal use only. No accounts. Still an experiment: keep infrastructure simple.

---

## Information Architecture

Two modes, toggled by a tab strip in the header:

### Plan mode (default)
- Scrollable list of gallery cards
- Filter strip below header: **All · Closing Soon · My Visit** · one chip per neighborhood present in data
- Each card is a full-width 3:2 aspect-ratio image with text overlaid at the bottom via gradient
- Tapping a card opens the Detail overlay

### Walk mode
- Full-screen Leaflet.js map (Esri Dark Gray Canvas basemap + street labels, no API key; replaced CartoDB dark Oct 24 2026)
- Markers for all **saved** galleries that have lat/lng populated in the XLSX
- Bottom sheet below map shows **saved shows only** (unseen first, then seen)
- Tapping a walk card or map marker opens the Detail overlay

### Detail overlay
- Full-screen fixed panel, slides up from bottom
- Shows: gallery name, show title, artist(s), closing info, address, hours, website link, full-size hero image
- Save button (◇/♦ diamond icon) and Mark Seen button
- Close button returns to previous mode
- **No description field** — drop it entirely

## Design Direction

Reference: the live page as generated by `generate_brief-v3.py` (the last generated copy is `Gallery_Brief.html` at the repo root until Build 1 removes it; the generator is archived in Josh's Dropbox). Build 1 must reproduce it exactly.

### Typography
- Headlines / gallery names / UI: **Bebas Neue** (Google Fonts)
- Body / show info: **Spectral** (Google Fonts)

### Color palette (CSS custom properties)
```css
--ink:         #1a1a1e;
--paper:       #f6f4f0;
--paper-dark:  #ece8e1;
--rule:        #d8d3ca;
--accent:      #c02818;   /* closing-soon stripe, urgent badges */
--accent-soft: #f9ecea;
--muted:       #8a8278;
--saved:       #1c5c38;   /* green — saved stripe + button */
--saved-soft:  #e6f2ec;
--seen:        #9a9490;
--mode-walk:   #1a3a5c;
```

### Layout
- Full app-shell: `html, body { height: 100%; overflow: hidden; }`
- Header: paper background (`--paper`), title ("NYC Photo Shows") left, mode toggle right
- Mode-bar below header title row: context text + closing-soon pulse dot (plan mode) or saved count (walk mode)
- Filter bar below mode-bar; scrollable horizontally
- Content panel scrolls independently
- Mobile-first; `max-width: 480px` centered on desktop

### Cards (image-forward, Option A from reference)
- Full-width, `aspect-ratio: 3/2`, `overflow: hidden`
- Image: `object-fit: cover`, fills the card
- Gradient overlay on top of image: `linear-gradient(to bottom, transparent 28%, rgba(8,8,8,0.55) 62%, rgba(8,8,8,0.94) 100%)`
- Text (artist, show title, gallery, closing date) overlaid absolutely at the bottom of the card, white type
- **No-image placeholder:** when `thumb` is empty, omit the `<img>` tag; card background is `var(--paper-dark)` and gradient overlay remains, making the text area dark and readable. No explicit placeholder text needed — the card still shows all text info.
- Closing soon: left red stripe (`4px` wide, `::after` pseudo-element, `background: var(--accent)`)
- Saved: top green stripe (`3px` tall, `::before` pseudo-element, `background: var(--saved)`)
- Seen: `filter: grayscale(0.7) brightness(0.65)` on the image; seen checkmark overlay top-left; artist name opacity reduced
- Save button: glassy circle top-right (`background: rgba(0,0,0,0.38)`, `backdrop-filter: blur(6px)`); filled green when saved
- Card tap → opens Detail overlay (not the save button tap)

## Data Model

All data lives in `gallery/data/` as JSON. The spreadsheet that preceded it is retired (archived in Josh's Dropbox).

### `galleries.json` — array, one object per gallery (stable facts)

| Field | Type | Notes |
|---|---|---|
| `id` | string | Slug of the gallery name. **Never change an existing id**: saved/seen state is keyed on it |
| `name` | string | |
| `neighborhood` | string | Grouping + filter chips |
| `status` | `"open"` \| `"closed"` \| `"relocating"` | Only `open` galleries render |
| `address`, `hours`, `website`, `notes` | string \| null | `notes` is free text |
| `isMuseum` | bool | |
| `lat`, `lng` | number \| null | |
| `exhibitionsUrl` | string \| null | New, empty for now. For the data-gathering redesign |
| `photoFocus` | `"specialist"` \| `"sometimes"` \| null | New, empty for now |

### `shows.json` — `{ "updated": "YYYY-MM-DD", "shows": [...] }` (current exhibitions, rewritten by each refresh)

| Field | Type | Notes |
|---|---|---|
| `id` | string | Currently equals `galleryId` (one show per gallery), which keeps existing saved/seen state valid. If multiple shows per gallery are ever needed, that's a deliberate migration |
| `galleryId` | string | Joins to `galleries.json` |
| `title` | string | |
| `artists` | string \| null | Page shows "Group Exhibition" when null |
| `closes` | `"YYYY-MM-DD"` \| `"ongoing"` \| null | |
| `image` | string \| null | Direct image URL; null → placeholder card |
| `isPhotography` | bool \| null | New, empty for now (Build 2 / data gathering) |

**Derived on the page, not stored:** days left, closing-soon (≤7 days), artist fallback, hiding shows whose closing date has passed, neighborhood colors.

**Seed:** converted from the spreadsheet on 2026-10-24: 46 galleries (43 open), 40 shows. Verified to match the generator's output exactly (same 40 ids; titles, dates, images, coordinates identical).

## Technical Decisions

- **Plain static files, no build step:** `gallery/index.html`, `gallery/app.js`, `gallery/style.css`. The page fetches `data/galleries.json` and `data/shows.json` at load. No framework. Leaflet and Google Fonts from CDN as before.
- **No generator.** Retired 2026-10-24. The refresh edits data files only; it never touches page code.
- **URL:** `joshuaseidenphotography.com/gallery/`. Root `_redirects` sends `/Gallery_Brief.html` (and Netlify's pretty-URL form `/Gallery_Brief`) to `/gallery/` with a 301.
- **Personal state (Build 1):** unchanged, browser localStorage with keys `gallery-savedIds` and `gallery-seenIds`. **Keep these exact keys** so Josh's current lists survive the move.
- **Personal state (Build 2, planned):** saved / seen / hidden move to a Netlify Function + Netlify Blobs store, read live by the page, protected by a personal key entered once per device. The weekend refresh reads hides and records them in the data files so hidden shows aren't re-added.
- **Map:** Esri World Dark Gray Base + Reference tile layers, `maxNativeZoom: 16`, `maxZoom: 19`, attribution "Tiles © Esri — Esri, HERE, Garmin, © OpenStreetMap contributors".
- **Scripts:** `gallery/scripts/hunt_images.py` fills/validates show images in `shows.json` (needs open network). Never clears an image on a network failure, only on a definitive 4xx/5xx.

## Workflow

- **Builds: AI Workshop** (autonomous, branch-per-step, PRs, Netlify deploy previews, Josh merges by hand). **Planning and visual prototyping: Josh's laptop.** See `claude-context/dev-workflow-ai-workshop.md` in Josh's Dropbox.

## Shared Infrastructure

This repo, its Netlify site and the domain are shared with Josh's photography portfolio (root files: `index.html`, `about.html`, `contact.html`, `style.css`, `images/`). Rules:
- Gallery work touches only `gallery/` and the root `_redirects` file. Never edit portfolio files.
- Never force-push. Merges to `main` are by Josh only.
- The Workshop token can technically write portfolio files; this is accepted for now (decision 2026-10-24). Revisit if risk increases or when Gallery Thing moves to its own domain.
